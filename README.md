# Student Placement Prediction System (ML + FastAPI + Docker + CI/CD + Render)

End-to-end MLOps project: a classifier predicts whether a student gets placed, served via FastAPI,
containerised with Docker, tested with Pytest, built/tested/deployed through GitHub Actions to Render.

## Project structure
```
data/            generate_dataset.py, student_placement.csv (1500 rows)
src/             config.py, train.py (model comparison + persistence)
app/             main.py (FastAPI), schemas.py (Pydantic validation)
tests/           test_api.py, test_model.py, conftest.py
models/          trained model + metrics (generated by training)
.github/workflows/ci-cd.yml
Dockerfile, render.yaml, requirements*.txt
```

## Dataset
Synthetic, reproducible (seed 42): `cgpa, iq, internships, projects, certifications,
communication_skills, backlogs, extracurricular` -> `placed` (0/1). Regenerate with
`python data/generate_dataset.py`. You may replace the CSV with a real dataset using the same columns.

## Run locally
```bash
python -m venv venv && source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements-dev.txt
python -m src.train
uvicorn app.main:app --reload
```
Swagger UI: http://127.0.0.1:8000/docs

## Tests
```bash
pytest --cov=app --cov=src
```

## Docker
```bash
docker build -t placement-api .
docker run -p 8000:8000 placement-api
```

## API
| Method | Path | Description |
|---|---|---|
| GET | `/` | Welcome message |
| GET | `/health` | Liveness + model status |
| GET | `/model-info` | Training metrics |
| POST | `/predict` | Single prediction |
| POST | `/predict/batch` | Up to 500 predictions |

Example:
```bash
curl -X POST http://127.0.0.1:8000/predict -H "Content-Type: application/json" \
 -d '{"cgpa":8.2,"iq":110,"internships":2,"projects":3,"certifications":2,"communication_skills":7.5,"backlogs":0,"extracurricular":1}'
```

## CI/CD (GitHub Actions)
`test` (train + pytest) -> `docker` (build, run, curl smoke test) -> `deploy` (Render deploy hook, main branch only).

## Deploy on Render
1. Push repo to GitHub.
2. Render dashboard -> **New + -> Web Service** -> connect repo -> Runtime **Docker**, Health Check Path `/health`
   (or use **New + -> Blueprint** with `render.yaml`).
3. Service **Settings -> Deploy Hook** -> copy URL.
4. GitHub repo **Settings -> Secrets and variables -> Actions** -> add `RENDER_DEPLOY_HOOK_URL`.
5. Open `https://<your-service>.onrender.com/docs` and test endpoints in Swagger UI.
